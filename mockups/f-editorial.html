01序

重たくない「いっしょ」の、四つの約束。

画面共有も、カメラも、重い 3D 空間もいらない。ブラウザのなかで、カーソルだけでゆるくつながる。そのために決めたこと。

i.

カーソルだけの、ゆるい繋がり

顔出しも声出しもなし。お互いの動線だけが伝わる、ちょうどいい存在感。

ii.

URL を、ひらくだけ

インストールはいらない。低スペックな PC やスマホからでも、ブラウザ 1 つで 1 秒で。

iii.

mod で、なんでも足せる

ペン、動画、付箋。ワールドの機能は URL から読み込む mod。ゼロトラストの Worker サンドボックスで安全に動く。

iv.

中央を、持たない

サーバー同士が連合する。どのサーバーの人ともフレンドになり、相手の部屋に入れる。

Origin
ブラウザ 1 つで、チルで集中できる自分だけの環境。そこに友達を呼べたら、最高じゃん。
— Ubichill のはじまり
02目次

はじめる

遊びに行く、建てる、作る、参加する。読みたいところから。

  1. a.アプリを開くubichill.com でアカウントを作って、すぐにホームワールドへ。ubichill.com
  2. b.自分のサーバーを建てるHelm チャート 1 つで k8s に。global.domain を決めるだけ。セルフホスト
  3. c.mod をつくる@ubichill/sdk と ubi mod create で雛形から。SDK
  4. d.ワールドを書くWorld as Code。YAML 1 枚が、ワールドの唯一の真実。World as Code
  5. e.開発に参加するIssue も PR も歓迎。PR は日本語でできればお願いします。GitHub
03ある一日

こんな使い方

同じ部屋が、時間によって作業場にも、アトリエにも、上映会場にもなる。

  1. 09:00

    もくもく作業会

    カメラなしで、誰かがいる気配だけ。付箋に今日のタスクを貼って、それぞれの作業へ。

  2. 13:00

    お絵描き・ホワイトボード

    ペンを手に取って、そのまま描く。打ち合わせの図も、ただの落書きも。

  3. 19:00

    イベント・展示・勉強会

    ワールドを URL で配る。誰が入れるかは公開範囲で決める。

  4. 22:00

    動画・映画の同時視聴

    再生位置はみんなで同期。弾幕を流せば、上映会が一気ににぎやかに。

04索引

ワールドでできること

標準の mod と、部屋のまわりの仕組み。足りないものは mod で足す。

カーソルアバター
.cur のカーソルテーマが、そのままアバターに。指す・待つ・つかむ、状態ごとに姿が変わる。
ペン・消しゴム
トレイから手に取って描く。線はその場の全員に同期される。
動画・ライブの同時視聴
動画もライブも。プレイリストで順番を待つ。
付箋
今日のタスク、イベントの告知。部屋に貼っておける。
弾幕
コメントを画面に流す。
スマホコントローラー
スマホをタッチパッド代わりにして、大きな画面のワールドを動かす。
ホームワールドとランチパッド
ログインしたら、自分のホームへ。部屋の移動も設定も、部屋の中の HUD から。
フレンド・招待・リクエストインバイト
フレンドを部屋に招く。招待のみの部屋には、入れてほしいと頼める。
公開範囲
誰に見えて、誰が入れるか。部屋ごとに四つから選ぶ。
パブリックフレンド+フレンドのみ招待のみ
05付録

作る人へ

mod は Worker で隔離され、@ubichill/sdk だけに依存する。ワールドは YAML で宣言する。

note 1権限は、使うときに聞く

危険度ごとに、初回使用時だけ確認する。ブラウザがカメラの許可を聞くのと同じように。決めたことは覚えておく。

safe描画・状態の同期。確認なし。
sensitive外部への接続。ドメインごとに確認。
dangerous強い権限。厳格に確認。

note 2宣言は書かない

mod が必要とする権限は、ビルド時に Worker のコードを静的解析して自動で導き出す。開発者が手で書く manifest はない。

note 3軽さのための分離

UI はブラウザで完結する CSR。部屋の同期は、独立した Go のサーバーが WebSocket で受け持つ。

Browser (Vite, CSR) ├─ mod Worker × n … sandbox └─ WebSocket ──▶ Go instance └─ API / DB
06連合と自宅

自分のサーバーで、みんなとつながる。

中央のサーバーは置かない。自分で建てたサーバーからも、ほかのサーバーの部屋へ行ける。

部屋のことは部屋のサーバー、
人のことはその人のホームのサーバーが決める。

フレンドの申請や招待は、ActivityPub（AS2）の形でサーバーからサーバーへ届く。署名は Ed25519 と RFC 9421。部屋には住所があり、どのサーバーの部屋にも入れる。

chill-room@yokan.example

Helm チャート 1 つで建つ

ドメインを決めて入れるだけ。DB のパスワードは自動生成され、メール認証を使わない構成もとれる。
