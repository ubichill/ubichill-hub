Get started

Ubichill をはじめる

遊びに行くだけなら URL を開くだけ。自分の場所がほしくなったら、サーバーも mod もワールドも、ぜんぶ自分の手でつくれます。

  • アプリを開く

    ubichill.com でアカウントを作って、すぐにホームワールドへ。

  • 自分のサーバーを建てる

    Helm チャート 1 つで Kubernetes に。DB も同梱。

  • mod をつくる

    @ubichill/sdk と ubi mod create で、ワールドに機能を足す。

  • ワールドを書く

    World as Code。YAML 1 枚がワールドの唯一の真実になる。

  • 開発に参加する

    Issue / PR 歓迎。PR は日本語で OK。公式 mod だけ作る、もウェルカム。

Whiteboard

ペンを持って、同じキャンバスに同時に描ける。

Event

イベント・展示・勉強会

World

ワールドでできること

ワールドはエンティティと mod の組み合わせ。公式の mod だけでも、日常の「いっしょにいる」はだいたいできます。

ワールドエディタ

ヒエラルキーからエンティティを置いて、mod のコンポーネントを並べるだけ。保存した内容はそのまま YAML として書き出せます。

For builders

つくる人のための Ubichill

ワールドは YAML、機能は mod。どちらも URL で配れて、権限はユーザーが握る。

mod をつくる

状態は Ubi.state で宣言するだけで、全員に同期される。

// mods/like/src/button.worker.tsx
const likes = Ubi.state.sync(0);

Ubi.ui.render(() => (
  <button onClick={() => likes.set(likes.get() + 1)}>
    いいね {likes.get()}
  </button>
));

World as Code

Kubernetes の CRD と同じ形。URL がワールドの名前。

apiVersion: ubichill.com/v1alpha1
kind: World
metadata:
  name: chill-room
spec:
  displayName: チルな作業部屋
  capacity: { max: 20 }
  dependencies:
    - name: pen
    - name: video-player

権限はユーザーのもの

使う API からビルド時に自動導出。初回使用時にだけ確認する。

  • safe描画や自分の状態。確認なしで動く
  • sensitive外部への fetch など。接続先ごとに確認
  • dangerous強い権限。シールド設定で拒否もできる
Servers

どのサーバーの人とも、同じ部屋に

Ubichill は中央のサーバーを置きません。部屋のことは部屋のサーバーが、人のことはその人のホームのサーバーが決めます。

サーバー間の連合

ActivityPub（AS2）の形で、フレンド申請も招待もサーバーをまたいで届く。署名は Ed25519 + RFC 9421。

ubichill.com
chill.example
yokan.dev
部屋の住所 chill-room@chill.example
パブリック フレンド+ フレンドのみ 招待のみ

自分のサーバーを建てる

global.domain を決めるだけで、Ingress も CORS も認証の URL も導出されます。

# Helm チャート 1 つで
helm repo add ubichill https://ubichill.github.io/ubichill
helm install ubichill ubichill/ubichill \
  -n ubichill --create-namespace \
  --set global.domain=<your-domain>
CSRVite の完全 CSR。UI はブラウザに閉じる
Goインスタンス通信は独立した WebSocket サーバー
DB 同梱PostgreSQL のパスワードも自動生成
